**先说结论：这个文件不是坏了，是被公司加密软件套了壳；但桌面上那份带「-」的文件是完好的未加密原件。**

我对比了两个文件的二进制内容：

| | `…101210.pdf` | `…101210-.pdf` |
|---|---|---|
| 文件头 | `%TSD-Header-###%` | `%PDF-1.4` |
| 结构 | 4096 字节头 + 220×4096 字节密文块 | 正常的 PDF 结构 |
| 内容 | 熵 7.95、4096 字节块无一重复，是真正的加密数据 | 29 页，2011 年 Distiller 生成，标题就是“压缩机性能试验装置操作说明书101210.doc” |

`%TSD-Header-###%` 是**天锐绿盾**透明加密的标志。所以那份带 `-` 的并不是通过“解析”得到的，而是一份**未加密的原件**，多半是发件人那边直接给的。

**为什么在这台电脑上做脚本也解不开**

绿盾采用驱动层透明解密：只有当白名单进程（Word、Excel、Acrobat）读文件时，它才在内存里把内容解密，密钥和企业账号绑定。我查了你的电脑：没有绿盾的进程、服务、驱动，注册表里也没有，更没有企业密钥。因此任何脚本在这里读到的都只能是密文。网上那些开源工具也一样，作者明确要求“必须在装了绿盾的电脑上运行”，比如 [GreenShieldDecrypter](https://github.com/Swaggymacro/GreenShieldDecrypter)。

**拿到明文的三种办法：从最省事到最麻烦**

1. 让发件人重新发一次：他在自己电脑上右键 → 选择“解密外发”或“申请解密”，再发给你。你手上那份 `-` 应该就是这么来的，最省事。
2. 在装了绿盾的公司电脑上打开这份 PDF，另存或打印成 PDF 再传出来。
3. 找 IT 走解密审批流程。

## 就算下载到、解开、逆向了，也没用

绿盾的密钥模型是这样的：

```
每家企业一把“企业密钥” → 存在公司服务器上 → 分发给每台客户端 → 客户端用它封装每个文件的密钥
```

你文件头里那 152 字节，就是用**你们公司那把企业密钥**封装的文件密钥。

- 从网上下载的客户端，是**别人家**的密钥；
- 逆向客户端，能拿到的是**算法**和**格式**；
- 拿不到的是**你们公司那把密钥**——它只存在于两台地方：公司服务器、当年那些电脑的客户端缓存里。

这两样你都没有。所以：**能逆出算法，解不开文件。** 这就是为什么 GitHub 上四个解密工具，没有一个是离线算的，全部是“借本地驱动”。
