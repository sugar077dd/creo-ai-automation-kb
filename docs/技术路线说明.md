# Creo 自动建模技术路线（实测版）

> 环境：Windows 10 x64 · Creo Parametric 12.4.4.0 · Python 3.13 · MSVC 2022 (14.44) · 项目 MCP_CREO_MechDog 0.20.0

---

## 一、总体架构：五层

```
┌─────────────────────────────────────────────────────────────┐
│ 1. 调用层   run_plan.py（我们的脚本，MCP 客户端）             │
│             读取 plan.json → 通过 MCP 协议调用工具            │
└───────────────────────────┬─────────────────────────────────┘
                            │ MCP over stdio（JSON-RPC）
┌───────────────────────────▼─────────────────────────────────┐
│ 2. 服务层   server.py（MechDog，Python，107 个 MCP 工具）      │
│             creo_execute_plan / creo_get_job / ...            │
│             职责：参数校验、任务落盘、状态机、结果汇总          │
└───────────────────────────┬─────────────────────────────────┘
                            │ 写任务目录（文件即队列）
┌───────────────────────────▼─────────────────────────────────┐
│ 3. 调度层   bridge.py（Python）                               │
│             找到/启动 worker，管理 Toolkit 通道锁、超时、重试   │
└───────────────────────────┬─────────────────────────────────┘
                            │ 启动子进程
┌───────────────────────────▼─────────────────────────────────┐
│ 4. 执行层   creo_worker.exe（C++，链接 Creo Toolkit）          │
│             ProEngineerConnect 连 Creo                        │
│             元素树建模：草图 → 拉伸 → 孔 → 圆角 …              │
└───────────────────────────┬─────────────────────────────────┘
                            │ Creo Toolkit C API（异步模式）
┌───────────────────────────▼─────────────────────────────────┐
│ 5. CAD 层   Creo Parametric 12（xtop.exe）                    │
│             生成原生参数化特征、保存 .prt、导出预览图           │
└─────────────────────────────────────────────────────────────┘
```

**关键点：我们（调用层）只负责“把形状写成 JSON”，其余四层都是 MechDog 提供的。**

## 二、数据流：从一张图到一个 .prt

### 1. 图纸 → 坐标（make_plate.py）

我们的生成脚本把图纸尺寸翻译成几何坐标，例如这张 890×890 的板：

- 底边平段 412（x: 239 → 651）
- 两侧 R445 圆弧：圆心 (239,445) / (651,445)，与底边相切
- 顶部倒角 51×51、57×57
- 两个 Ø51 孔

脚本用 `math.atan2` 精确计算圆弧端点，避免四舍五入导致“开口轮廓”（曾经因为 0.0000035 mm 的缝隙失败）。

### 2. 坐标 → plan JSON

```json
{
  "model_name": "plate_890",
  "model_type": "part",
  "operations": [
    {
      "op": "sketch", "label": "profile", "plane": "XY",
      "endpoint_policy": "weld", "snap_endpoints": true,
      "closure_tolerance_mm": 0.02, "max_endpoint_move_mm": 0.05,
      "entities": [
        {"type": "line",  "name": "l_top",  "start": [51,890], "end": [833,890]},
        {"type": "polyline", "name": "a_left", "points": [[0,445],[...],[239,0]], "closed": false},
        {"type": "circle", "name": "hole_left", "center": [388,833], "radius": 25.5}
      ]
    },
    {"op": "extrude", "label": "plate", "sketch": "profile", "depth": 2},
    {"op": "save"}
  ]
}
```

支持的操作有 40+ 种：`sketch / extrude / revolve / hole / round / chamfer / pattern / mirror / sheetmetal_planar_wall / assemble_component / export / drawing_*` 等。

### 3. plan JSON → MCP 调用

`run_plan.py` 通过 MCP stdio 启动 `server.py`，依次调用：

| 步骤 | 工具 | 作用 |
|---|---|---|
| ① 连接检查 | `creo_session_status` | 探测 Toolkit 通道，返回 `connected: true` |
| ② 就绪检查 | `creo_startup_status` | 等待 `state: ready`（避免撞上 building_worker） |
| ③ 提交 | `creo_execute_plan` | 校验 plan，落盘成任务，返回 `job_id` |
| ④ 轮询 | `creo_get_job` | 每 2 秒查一次，直到 `succeeded / failed` |

### 4. 任务目录（文件即队列）

```
jobs/<job_id>/
├─ request.json        原始请求
├─ job.json            状态机（queued → running → succeeded/failed）
├─ native.log          worker 的逐步日志
├─ native_result.json  建模结果（特征列表、体积等）
├─ inspection-*.json   独立校验（has_solid / healthy / 特征数）
└─ output/preview.jpg  自动生成的预览图
```

### 5. worker 内部的建模机制（重点）

worker 用 Creo Toolkit 的 **元素树（element tree）** API 建特征，核心分两步：

#### 第一步：把草图做成独立特征

```c
// 1) 构造草图特征的元素树
root = ProElementAlloc(PRO_E_FEATURE_TREE);
    PRO_E_FEATURE_TYPE = PRO_FEAT_CURVE
    PRO_E_CURVE_TYPE   = PRO_CURVE_TYPE_SKETCHED
    PRO_E_STD_SECTION
       ├─ PRO_E_STD_SEC_SETUP_PLANE（参考面 + 视图方向 + 方向参考）
       └─ ...

// 2) 先建"不完整特征"，拿到内部草图对象
ProFeatureWithoptionsCreate(..., PRO_FEAT_CR_INCOMPLETE_FEAT, ...);
ProFeatureElemtreeExtract(&feat, ..., &root);
ProElemtreeElementGet(root, {PRO_E_STD_SECTION, PRO_E_SKETCHER}, &sk);
ProElementSpecialvalueGet(sk, NULL, &section);

// 3) 往草图里加实体（直线/圆弧/圆）
ProSectionEntityAdd(section, &line_def, &id);

// 4) 求解 + 重定义补全
ProSectionSolve(section, &err);
ProFeatureWithoptionsRedefine(NULL, &feat, root, PRO_FEAT_CR_NO_OPTS, ...);
```

#### 第二步：拉伸引用这个草图特征

```c
root = ProElementAlloc(PRO_E_FEATURE_TREE);
    PRO_E_FEATURE_TYPE        = PRO_FEAT_PROTRUSION
    PRO_E_FEATURE_FORM        = PRO_EXTRUDE
    PRO_E_EXT_SURF_CUT_SOLID_TYPE = PRO_EXT_FEAT_TYPE_SOLID
    PRO_E_REMOVE_MATERIAL     = PRO_EXT_MATERIAL_ADD
    PRO_E_STD_SECTION → PRO_E_SEC_USE_SKETCH  （引用草图特征的选择对象）
    PRO_E_STD_DIRECTION       = ±1
    PRO_E_STD_EXT_DEPTH
       ├─ PRO_E_EXT_DEPTH_FROM → PRO_EXT_DEPTH_FROM_NONE
       └─ PRO_E_EXT_DEPTH_TO   → PRO_EXT_DEPTH_TO_BLIND + 数值

ProFeatureWithoptionsCreate(model_sel, root, NULL, ...);
```

**这里有两个我们踩过的坑：**

1. 草图必须做成**独立特征**（`PRO_FEAT_CURVE`），不能塞进拉伸的“不完整特征”里——否则 `ProSectionEntityAdd` 返回 `-48 CANT_MODIFY`（同步模式）；
2. 跨模型复制特征树会**参考失效**（特征带红色错误标记），所以“模板 + 参数”比“克隆特征树”可靠。

### 6. 保存与校验

- `save` 操作保存 `.prt.N`；
- worker 会从磁盘**重新加载**并比对特征、尺寸、体积（`saved_file_reloaded_and_verified`）；
- 独立 inspection 输出 `has_solid / healthy / features / bodies / unit`。

## 三、运行环境的关键约束（实测踩坑）

### 1. 必须“同权限级别”：Creo 和 worker 都以管理员运行

PTC 的异步 RPC 通道要求创建**全局命名对象**：

| 组合 | 结果 |
|---|---|
| Creo 普通 + worker 普通 | ❌ `probe_timeout` / `portmapper must run` |
| Creo 管理员 + worker 普通 | ❌ 完整性级别隔离，互相看不见 |
| **Creo 管理员 + worker 管理员** | ✅ `toolkit_code: 0` |

> 系统层面：普通用户令牌没有 `SeCreateGlobalPrivilege`；给用户授予该权限后仍然失败（实测），说明还要求 Creo 本身提权创建通道。

### 2. 只能开一个 Creo 实例

多个会话会导致 `toolkit_code: -36`（会话歧义）。

### 3. 模型名不能重复

同名模型已在会话中时，任务会在 `connect` 阶段失败。我们的脚本自动加时间后缀规避。

### 4. Creo 版本

MechDog 官方验证 9 / 10 / 12；**11 未验证**（我们最初在 11 上失败，虽混有权限因素，但不能排除兼容性）。建议 12。

### 5. 计划任务方式不可靠

用 `schtasks` 以“最高权限”启动时会话/提权上下文对不上，实测仍需手工“右键 → 以管理员身份运行”。

## 四、我们做了什么 vs 复用了什么

| 工作 | 来源 |
|---|---|
| Toolkit 元素树建模、草图求解、特征创建 | ✅ MechDog `native/*.cpp`（开源） |
| MCP 服务、任务队列、校验、预览图 | ✅ MechDog `server.py` / `bridge.py` |
| 环境搭建（MSVC + NuGet SDK 绕过安装器） | 我们 |
| 图纸 → 坐标 → plan JSON | 我们（`make_plate.py`） |
| 调用封装、日志、错误定位 | 我们（`run_plan.py`） |
| 权限/会话问题的定位与验证 | 我们 |

## 五、扩展到“Inventor → Creo”的路径

```
Inventor 模型
   │ ① 导出参数/特征（Inventor API 或 STEP + 特征识别）
   ▼
中间数据（JSON：板厚、外形轮廓点、孔位、折弯线…）
   │ ② 映射层（需要开发，核心工作量）
   ▼
plan JSON（sketch / extrude / hole / sheetmetal_*）
   │ ③ 现有执行链（已打通）
   ▼
Creo 原生可编辑特征 + .prt
```

**② 是真正的工作量所在**：把 Inventor 的拓扑（面、边、折弯）映射成 Creo 的草图与特征参数。
