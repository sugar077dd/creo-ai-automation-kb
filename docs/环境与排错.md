## 二、权限：必须"同级别提权"

PTC 异步 Toolkit 通道依赖全局命名对象（需要 `SeCreateGlobalPrivilege` 等），实测组合如下：

| Creo | worker / MCP 服务 | 结果 |
|---|---|---|
| 普通 | 普通 | ❌ `probe_timeout` / `Can not use registry for rpc mapping` |
| 管理员 | 普通 | ❌ 完整性级别隔离，互相不可见 |
| 普通 | 管理员 | ❌ `toolkit_code: -4`（找不到会话） |
| **管理员** | **管理员** | ✅ `toolkit_code: 0`，`connected: true` |

补充：给普通用户授予"创建全局对象"策略后**仍然失败**，说明还要求 Creo 本身以提权方式创建通道。

### 其他权限相关结论

- 用 `schtasks` 创建的"最高权限"任务，实测仍出现会话/令牌不匹配，**不建议依赖**；
- 可靠方式：**右键 → 以管理员身份运行**（Creo 与执行脚本各一次）。

## 三、常见错误码与原因

| 现象 | 原因 | 处理 |
|---|---|---|
| `Can not use registry for rpc mapping. portmapper must run` | 客户端无权限写端口映射 | 以管理员运行 |
| `probe_timeout` | 权限级别不一致 / Creo 未就绪 | 统一提权；等 Creo 进主界面 |
| `toolkit_code: -4` | 无会话（管理员进程看不到普通 Creo） | 让 Creo 也以管理员启动 |
| `toolkit_code: -36` | 多个 Creo 会话，歧义 | 只保留一个实例 |
| `New model name already exists in the Creo session` | 同名模型已在会话中 | 换模型名（脚本已自动加时间后缀） |
| `Extrude ... ProFeatureWithoptionsCreate=-1` + "open end(s)" | 草图轮廓未闭合 | 用多段线代替圆弧，端点坐标严格一致 |
| `endpoint_policy weld needs max_endpoint_move_mm` | weld 策略缺少上限 | 补 `max_endpoint_move_mm` |
| `Automatic startup is disabled` | `auto_start_creo=false` 时服务拒绝提交 | 改回 `true` |
| `Explorer launch request failed (HRESULT=-2147352567)` | 服务用 Explorer COM 启动 Creo，受限 | 手动以管理员启动 Creo |

## 四、版本差异

- MechDog 官方验证：Creo **9 / 10 / 12**；
- **Creo 11 未验证**（最初在 11 上失败，混有权限因素，但不能排除兼容性）；
- 建议统一使用 Creo 12。

---

## 五、其他实操注意

1. **只能开一个 Creo 实例**；
2. 首次启动 Creo 约需 1~2 分钟，脚本需等 `state=ready` 再提交；
3. 提交计划后必须保持 MCP 连接并轮询 `creo_get_job`，否则任务停在 `waiting_for_channel`；
4. 草图轮廓建议用 **polyline** 而非 arc（端点精度问题会导致"开口轮廓"）；
5. 执行前确认 `config.json` 的 `creo_root` 指向实际安装目录，改完后需重新编译 worker。
